# Migration Playbook — смена типа поля в Convex

> Повторяющаяся задача: изменить ТИП существующего поля (`string→number`,
> `string→v.id`, drop поля). Convex валидирует ВСЕ доки против задеплоенной
> схемы на каждом деплое, а мутация пишет через задеплоенную схему — поэтому
> строгую смену типа нельзя сделать в один шаг. Ниже — стандарт команды.

## Закон Convex (почему нужен «мост»)

- Деплой строгой схемы `v.number()` при старых строках → **падает** (валидация существующих доков).
- Мутация пишет `number`, а задеплоена `v.string()` → **write отвергается**.
- Рантайм-API отключить валидацию из миграции **нет** (`schemaValidation` — deploy-time, глобальный). Override схемы «внутри миграции» невозможен.
- ⇒ Нужен ПРОМЕЖУТОЧНЫЙ деплой, где схема принимает старое И новое.

**Аддитивные изменения (новое `v.optional` поле) моста НЕ требуют** — деплой не конфликтует со старыми доками. Большинство изменений делай аддитивно.

---

## Паттерн A — expand-contract (union). БЕЗОПАСНЫЙ, дефолт команды ⭐

Валидация остаётся ВКЛ; permissive только меняемое поле.

1. **Widen** — поле в union (1 строка в его файле, схема разбита по доменам):
   ```ts
   // convex/schema/workloads.ts
   totalHours: v.union(v.string(), v.number()),   // было v.string()
   ```
   `npx convex deploy` → OK (принимает и строки, и числа).
2. **Migrate** — данные old→new (@convex-dev/migrations):
   ```
   npx convex run workloadMigrations:totalHoursToNumber
   ```
3. **Contract** — сузить до нового типа:
   ```ts
   totalHours: v.number(),
   ```
   `npx convex deploy` → OK (все доки уже number).

2 деплоя. Остальные таблицы валидируются строго весь процесс. Для важных данных — только так.

## Паттерн B — `schemaValidation:false` (global bypass). БЫСТРЫЙ, рискованный

Схема сразу в НОВОМ состоянии, вся валидация выкл на окно. Один сорт правки, но
**глобально без проверок** — плохой write в окне сохранится. Годится для
мелких/dev-баз, доверенного окна. Автоматизируется одной командой:

```
bash scripts/migrate.sh workloadMigrations:totalHoursToNumber
```
Скрипт: временно `{ schemaValidation: false }` в `schema.ts` → deploy → run
migration → восстановить строгую схему → deploy. См. `scripts/migrate.sh`.

⚠️ Оба деплоя выкатывают ВСЮ текущую ветку на цель — не только это поле.

---

## Когда что

| Случай | Паттерн |
|--------|---------|
| Новое поле (`v.optional`) | Ничего — аддитивно, деплой сразу |
| Смена типа, важные данные | **A (union)** |
| Смена типа, мелкая/dev-база, доверенное окно | B (script) |
| Много полей сразу (напр. массив-миграция) | A, одним permissive-окном на все |

## Данные транзитора всегда идемпотентны
`migrateOne` пропускает уже-мигрированные (`typeof x === "number"`) → повторный
прогон безопасен. Пиши миграции в `convex/*Migrations.ts` через
`migrations.define`.
