# Технический стек платформы MARS 2.0

## 1. Язык программирования

- **TypeScript** (основной язык, версия 6.x) — весь фронтенд и бэкенд.
- **Vue 3** (Composition API, SFC `.vue`) — фреймворк пользовательского интерфейса.
- **Framework7 9 + Framework7-Vue** — UI-библиотека мобильного/PWA-уровня.
- Вспомогательные языки сборки/служебных скриптов: **JavaScript** (`.mjs`, конфиги Vite), **Shell** (`scripts/*.sh`), **Python** (разовые миграционные утилиты данных).

## 2. База данных

- **Convex** (версия 1.38) — serverless реактивная база данных и backend-as-a-service.
  - Схема описана декларативно в `convex/schema.ts`.
  - Серверная логика (queries / mutations / actions) пишется на TypeScript внутри каталога `convex/`.
  - Данные индексируются (например `by_teacherId`, диапазонные индексы по датам) для O(1)/range-доступа.

### Что Convex использует «под капотом»

Convex — это **собственный движок базы данных, написанный на Rust** (документно-реляционная
модель, сериализуемые транзакции с оптимистичной конкуренцией, реактивный слой запросов).
Приложение никогда не пишет SQL напрямую — весь доступ идёт через TypeScript-функции Convex.

Для долговременного хранения движок Convex опирается на сменяемый **SQL-бэкенд**:

| Вариант развёртывания | Хранилище под движком |
|------------------------|------------------------|
| Self-hosted (open-source backend, Rust) | **SQLite** (по умолчанию), **PostgreSQL** или **MySQL** |
| Convex Cloud (управляемый) | тот же движок на размещённой SQL-инфраструктуре (детали провайдера скрыты) |

Итог: **СУБД проекта — Convex (свой движок на Rust поверх SQLite / PostgreSQL / MySQL)**.
PostgreSQL/MySQL/SQLite выступают лишь слоем байтового хранения; индексы, транзакции и
реактивность реализует сам Convex.
- Локальное хранилище клиента: **localForage** (IndexedDB) + **Pinia** с `pinia-plugin-persistedstate` для кэша состояния.

## 3. Операционная система / тип архитектуры

- **Тип архитектуры:** клиент-серверная, реактивная, **serverless**.
  - **Клиент:** SPA / **PWA** (Progressive Web App, `vite-plugin-pwa`), single-page приложение на Vue 3 + Framework7. Поддержка iOS ≥ 15, Safari ≥ 15, актуальные Chrome/Firefox.
  - **Бэкенд:** управляемая платформа Convex (serverless-функции, без собственного сервера приложений).
  - **Связь:** реактивные подписки Convex (`convex-vue`) — данные обновляются в реальном времени без ручного polling.
  - **Слой авторизации:** динамический RBAC (роли/права), JWT (`jose`), хеширование паролей (`bcryptjs`).
- **ОС среды разработки/сборки:** Linux (целевая среда выполнения backend — управляемая инфраструктура Convex; ОС-независимый клиент работает в любом современном браузере).
- **Среда выполнения сборки:** Node.js **22.22.2**.

## 4. Инструменты сборки и тестирования

- **Сборщик:** Vite 8.
- **Стили:** Tailwind CSS 3 + PostCSS + Sass.
- **i18n:** Paraglide JS (Inlang) — компиляция сообщений для фронтенда и бэкенда.
- **Тесты:** Jest (юнит), Playwright (E2E + компонентные).
- **AI-интеграция:** Vercel AI SDK + `@ai-sdk/google`, LiveKit (реалтайм-медиа).

## 5. Исходный код (фрагмент)

> Ниже — ключевой/уникальный модуль платформы: декларация схемы базы данных Convex

> поля и индексы. Полный листинг прикладывается отдельным текстовым файлом.

Файл `convex/schema.ts` — **1095 строк**. Ниже первые и последние строки листинга.

### Начало файла

```typescript
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

// ============================================================================
// MARS 2.0 Education Management System - Convex Schema
// Migrated from Pinia stores + D1/Prisma backend
// ============================================================================

export default defineSchema({
  // ==========================================================================
  // AUTHENTICATION & USERS
  // ==========================================================================

  /**
   * Users table - stores user accounts for authentication
   * Migrated from: Prisma User + UserRole models
   */
  users: defineTable({
    firstName: v.string(),
    lastName: v.string(),
    middleName: v.optional(v.string()), // Middle name/patronymic
    username: v.string(),
    email: v.string(),
    passwordHash: v.string(), // bcrypt hash
    roles: v.array(
      v.union(
        v.literal("ADMIN"),
        v.literal("TEACHER"),
        v.literal("STUDENT"),
        v.literal("PARENT")
      )
    ),
    avatar: v.optional(v.string()), // Profile picture URL or storage ID
    theme: v.optional(v.union(v.literal("light"), v.literal("dark"), v.literal("lavanda"), v.literal("coral"), v.literal("graphite"))),
    locale: v.optional(v.union(v.literal("ru"), v.literal("kk"), v.literal("en"))),
    phone: v.optional(v.string()),
    office: v.optional(v.string()),
    department: v.optional(v.string()),
    degree: v.optional(v.string()),
    createdAt: v.number(),
    updatedAt: v.number(),
  })
    .index("by_username", ["username"])
    .index("by_email", ["email"]),

  // ... (≈1000 строк описаний таблиц: журналы, дисциплины, расписание,
  //      оценки, тесты, посещаемость, RBAC-роли и др.) ...
```
