# Для чего мы высчитываем `totalHours` — детально

> Разбор: в системе **несколько разных** `totalHours` из разных доменов. Ниже —
> что каждый значит, как считается, кто потребляет и **зачем**. С `file:line`.

---

## 0. Коротко — 6 разных `totalHours`

| # | Сущность | Тип | Смысл одной строкой |
|---|----------|-----|---------------------|
| A | `rupEntry.totalHours` | `string` | **План** всего часов дисциплины в РУП (группа + индивидуальные) |
| B | `workloadItem.totalHours` | `number` | Сколько часов преподаватель ведёт по этой дисциплине (за назначение) |
| C | `workload.totalHours` (top) | `number` | Общая нагрузка преподавателя = Σ по дисциплинам |
| D | Calculator `plannedHours` | `number` | = `parseFloat(rupEntry.totalHours)` — план для сравнения с фактом |
| E | Calculator `actualHours`/`totalHours` | `number` | **Факт** — сумма часов проведённых уроков из журналов |
| F | `ktpDetail.totalHours` | `number?` | Часы темы в КТП (тематический план) — отдельный домен |

**Главная цепочка (ради чего всё):**
```
РУП (A) ──plannedHours(D)──► Калькулятор ──remaining = план − факт──► Отчёты (Формы 1/2/3) ──► тарификация/проверка
                                    ▲
                          факт (E) из журналов
```

---

## A. `rupEntry.totalHours` — ПЛАН часов дисциплины

**Что:** сколько всего часов заложено на дисциплину в Рабочем Учебном Плане.
Строка. `convex/schema/rup.ts` (`totalHours: v.string()`), тип
`src/types/rup-entry.ts:30`.

**Где задаётся:** форма РУП — `RupEntryPopup.vue:200` (`v-model="step.totalHours"`),
валидация `:947` (zod), сохранение `:1014`.

**Модель (уточнено владельцем 2026-07-22 — РЕЖИМНАЯ, не плоская сумма):**
`totalHours` = общий итог по **всем** учебным годам и семестрам, делится на
ОДИН из двух режимов:
```
Групповой режим:                     Индивидуальный режим (спец):
  Всего = Групповые + доп.индив         Всего = Индивидуальные
  Групповые = Теор + Лаб/практ          Групповые = 0, Теор=Практ=доп.индив=0
  Индивидуальные = 0
```
Общая форма (с нулями):
`totalHours = Групповые + individualAdditionalHours + individualHours`,
где `Групповые = theoreticalHours + labPracticalHours`.

⚠️ **Поля «Групповые» сейчас НЕТ** — владелец решил ДОБАВИТЬ его (перед
Теоретические/Лаб-практ). Текущий `targetGroup = totalHours − individualAdditionalHours`
(`RupEntryPopup.vue:630`) — приближение, которое НЕ вычитает `individualHours`
(чисто индивидуальные), поэтому для «спец» (всё в `individualHours`) даёт неверный
групповой таргет. После добавления поля: `Групповые` вводится напрямую.

Пример «Спец»: Всего=280, Индивидуальные=280, Групповые=0. Пример групповой:
Всего=280, Групповые=180 (Теор80+Практ100), доп.индив=100, Индивидуальные=0.

**Зачем считаем:**
1. **Норма нагрузки дисциплины** — сколько она должна занять за год.
2. **База распределения** — на теор/практ/индивидуальные (форма РУП авто-делит).
3. **План для отчётности** — уходит в калькулятор как `plannedHours` (см. D).

**Кто читает:** калькулятор (D), карточки/таблицы РУП
(`RupEntryTable.vue:106,109`, `RupEntryViewPopover.vue:97`,
`RupImportDialog.vue:89`, `DisciplineCatalog.vue:113`), окно добавления в
нагрузку (`WorkloadManagement.vue:634`), `rupStore.ts:67`,
`useEventFormDerived.ts:93`.

## B. `workloadItem.totalHours` — часы преподавателя по дисциплине

**Что:** сколько часов преподаватель реально ведёт по этой дисциплине в рамках
назначенной нагрузки. Число. `convex/schema/workloadItem.ts:66`,
`src/types/workload.ts:31`.

**Формула (`WorkloadManagement.vue:1111`, `recalculateItem`):**
```
totalHours = Math.round( Σ_i  hoursPerGroup_i × groupCount_i )
           = Math.round( Σ_i  (weeks_i × hours_i) × groupCount_i )
```
где i — семестры. Для строки `_ind` (индивидуальные) — аналогично, `:1087`.

**Зачем считаем:**
1. **Учёт нагрузки** — сколько часов «висит» на преподавателе по предмету.
2. **Слагаемое общей нагрузки** (C).
3. **Валидация генерации журналов** — wizard сверяет `hoursPerGroup` с расписанием.

**Кто читает:** отображение строк (`WorkloadManagement.vue:230,361,543`),
подвал (C), CSV-экспорт (`:1231,1272`), `workloadStore.ts:35`.

> ⚠️ Отличие от A: `workloadItem.totalHours` — это **групповые** часы назначения
> (главная строка), а индивидуальные вынесены в отдельную строку `_ind`. То есть
> нагрузка **уже разделяет** группу и индивидуальные — в отличие от РУП-`totalHours`
> (A), который их суммирует. Это корень расхождения #4 (см. §Расхождение).

## C. `workload.totalHours` (верхний уровень) — общая нагрузка преподавателя

**Что:** суммарная годовая нагрузка преподавателя в часах. Число.
`convex/schema/workloads.ts`, `src/types/workload.ts:46`.

**Формула (`WorkloadManagement.vue:971`, `totalCurrentWorkloadHours`):**
```
workload.totalHours = Σ  item.totalHours   (по всем строкам, включая _ind)
```
Сохраняется при записи нагрузки (`:1162`).

**Зачем считаем:**
1. **Тарификация** — общая нагрузка = основа расчёта ставки/оплаты преподавателя.
2. **Контроль лимитов** — не превышена ли норма часов.
3. **Сводка** — отображение в карточках (`:347,520`), `workloadStore.ts:51`.

## D. Calculator `plannedHours` — план в отчёте

**Что:** план из РУП, взятый как есть.
`teacher-workload-calculator.ts:383, 501, 826`:
```ts
const plannedHours = parseFloat(group.rupEntry.totalHours) || 0;
```

**Зачем считаем — ГЛАВНОЕ назначение totalHours:**
Сравнить план с фактом и вычислить **остаток** (`:412`):
```
remainingHours = Math.max(0, plannedHours − cumulativeHours)
```
Это ядро отчётности: сколько ещё осталось «отработать» по плану.

## E. Calculator `actualHours` / `totalHours` — ФАКТ из журналов

**Что:** фактически проведённые часы, посчитанные из уроков в журнале.
`teacher-workload-calculator.ts:476` (`totalHours = Σ lessonDates.hours`), агрегация
`:490,495,502,518`, годовая сумма `:862,867`.

**Связанные величины:** `actualHoursMonth` (за месяц), `cumulativeHoursYear`
(накопительно с начала года) — `:186-187,208-209,242,282,292`.

**Зачем считаем:** это «факт» в паре план/факт → строит **остаток** (D) и
заполняет **Формы 1/2/3** Excel-отчёта (`:299` «populates Form 1»; summary-строки
`plannedHours` vs `actualHours` — Форма 2, `:501-518`).

## F. `ktpDetail.totalHours` — часы темы в КТП (отдельный домен)

**Что:** часы на тему в Календарно-Тематическом Плане. `convex/schema/calendar.ts`
(`v.optional(v.number())`), тип `src/types/ktp.ts:32`.

**Считается/суммируется:** `useKtpDetail.ts:92-96` (Σ по темам),
`KtpPage.vue:325-332` (`ktpTotalHours`), форма `KtpDetailFormPopover.vue`.

**Зачем:** планирование уроков по темам внутри дисциплины (не про нагрузку
преподавателя и не про РУП-план напрямую). Отдельная ветка.

## Расхождение #4 — почему это важно для totalHours

Владелец подтвердил: **A (`rupEntry.totalHours`) включает индивидуальные часы**
(грандтотал = группа + индив + доп.индив).

Но:
- **B/C** (нагрузка) уже **разделяют**: главная строка = группа, `_ind` = индив.
- **D** (`plannedHours`) берёт **A целиком** (с индив) и сравнивает с **E**
  (факт по **групповым** урокам журнала).

Итог: для дисциплины с индивидуальными часами отчёт даёт **фантомный остаток**
ровно на индивидуальную часть (напр. «Спец 190»: план 190, групповой факт 0 →
«остаток 190», хотя все 190 — индивидуальные, которых нет в групповом журнале).

**Решение владельца — добавить явное поле «Групповые»** (перед Теор/Лаб-практ).
Тогда фикс #4 однозначен:
```
групповой план  = Групповые (= Теор + Лаб/практ)          → сравнивать с ГРУППОВЫМ фактом журнала
индивид. план   = individualHours + individualAdditionalHours → вести ОТДЕЛЬНО
```
Ключ: `individualHours` (чисто индивидуальные, «спец») ТОЖЕ вне группового плана,
не только `individualAdditionalHours`. Для «спец» групповой план = 0 → нет
фантомного остатка.

**Радиус:** +поле `groupHours` в схеме (`rupEntries`), инпут в `RupEntryPopup`,
backfill `groupHours = theoreticalHours + labPracticalHours` (через
`@convex-dev/migrations`), фикс калькулятора (`teacher-workload-calculator.ts:383,501,826`
брать `groupHours`, не `totalHours`), выравнивание нагрузки (главная строка=группа).
