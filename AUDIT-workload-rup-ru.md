## Три системных корня (объясняют большинство дефектов)

1. **Нет единого источника истины для «плановых часов».**
   `totalHours`, `sum(distributionEntries)`, `individualAdditionalHours`
   нигде не сверяются между собой. Каждый потребитель берёт своё поле:
   калькулятор → `totalHours`, страница нагрузки → сумму строк распределения,
   попап → `totalHours − individualAdditionalHours`.

2. **Валидация только на клиенте, только по-полю.**
   Сервер сохраняет всё как есть: часы — `v.string()` (проходит даже `'abc'`),
   нет перекрёстных проверок, `semesterId` кастуется через `as any`.

3. **Неатомарная запись нескольких документов.**
   Запись = N последовательных мутаций (запись + строки распределения +
   языковые варианты). Любой сбой оставляет частичное состояние.
   Атомарная мутация `createMultiLanguage` есть, но клиент её не вызывает.

# ЧАСТЬ 1 — WorkloadManagement (страница нагрузки)

## Критично

### 1. Часы 3-го семестра молча обнуляются
`src/pages/WorkloadManagement.vue:992-1017, 1101-1106`
`addSubjectFromRup` инициализирует только `weeks1="18"`, `weeks2="20"`,
`groupCount1/2="1"`. Строки распределения записывают `hoursPerGroup3`, затем
`recalculateItem` (L1017) читает `parseFloat(item.weeks3||'0')=0` и
`groupCount3=0`, перезаписывает `hoursPerGroup3="0"`. Двойное обнуление —
даже если заполнить `weeks3`, всё равно 0, пока не заполнен `groupCount3`.
Схема помечает все `*3`-поля опциональными → сохраняется без ошибки.
**Ввод:** год с 3 семестрами, распределение `["30","30","30"]` (план 90) →
сохранённый итог **61**, 30 часов 3-го семестра исчезают.

### 2. Позиционная привязка семестров
`src/pages/WorkloadManagement.vue:1007-1010`
`distributionEntries` привязываются к семестрам **по индексу массива**,
игнорируя `semesterId`/`academicYearId`. Строки не по порядку или из другого
учебного года попадают не в тот семестр.

## Высокая

### 3. `toFixed(1)` округляет недельные часы → сумма уходит от плана РУП ✅ ИСПРАВЛЕНО
`src/pages/WorkloadManagement.vue:1012, 1017, 1105`
Заполнение хранит точное `hoursPerGroupN = entry.hours`, но
`hoursN = (hours/weeks).toFixed(1)`; затем `recalculateItem` перезаписывает
`hoursPerGroup = weeks × округлённое`. Дрейф до `weeks×0.05`, умножается на
число групп.
**Ввод:** hours=48, weeks1=18 → 48/18=2.6667→"2.7" → 18×2.7=48.6 → итог **49**
вместо плана 48. groupCount=3 → **146** вместо 144.

**ИСПРАВЛЕНО (2026-07-22):** 3 места посева (L1012, L1051, L1078) `.toFixed(1)`
→ `.toString()` — недельные часы хранятся с полной точностью, `weeks × hours`
восстанавливает точный план. Инпут часов/неделю (L185): `v-model` →
`:value="formatHours(...)"` + `@input`, пишущий сырое значение обратно —
модель точная, отображение чистое. `recalculateItem` не тронут. Проверено:
48ч/18нед → 48 (было 49), groupCount 3 → 144 (было 146), 36ч/18нед → 36.

### 4. Два разных определения «плановых часов»
`src/services/teacher-workload-calculator.ts:383` vs страница L1007

отчёты дают разные числа. **(Причина — в РУП-подсистеме, см. Часть 2 №2.)**

### 5. Редактирование строки `_ind` уничтожает индивидуальные часы

арифметикой `weeks×hours`.

## Два решения, которые разблокируют исправления

### Решение А — канонические «плановые часы»
Какое поле истина?
1. **`totalHours` = групповые + индивидуальные** → на сохранении требовать
   `sum(distribution) + individualAdditionalHours == totalHours`. Совпадает с
   тем, что уже читает калькулятор.
2. **`sum(distribution)` — истина** → `totalHours` производный, калькулятор
   переходит на суммирование строк.
3. **Не уверен** → уточнить в колледже; пока держим Часть-Б, делаем очистку
   недоделанных фич + характеризационные тесты на ТЕКУЩЕЕ поведение.

### Решение Б — недоделанные фичи (импорт/дубль/выбор/каталог)
- **Удалить** — убрать вызовы + кнопки UI (быстро, откатимо из git).
- **Доделать** — реализовать недостающие методы стора (реальная разработка).
- **Сначала разведка** — проверить, на живых ли роутах, потом решить.

### Что делать в любом случае — ПЕРВЫМ
**Характеризационные тесты.** Тестов на арифметику часов сейчас **ноль**. Любая
правка `recalculateItem` или поля плановых часов вслепую = молчаливый регресс в
оплате/отчётности преподавателей. Сначала зафиксировать текущее поведение в
тестах, потом безопасно рефакторить.
